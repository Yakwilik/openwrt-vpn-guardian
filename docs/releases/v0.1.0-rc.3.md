Третий предварительный релиз OpenWrt VPN Guardian для **OpenWrt 24.10.4 с opkg**. Впервые публикуется полный комплект с модифицированным native *dnsmasq-full*, необходимым для корректного разделения обычного DNS и защищённых VPN-доменов.

## Что входит

Для каждой архитектуры в разделе **Assets** есть четыре IPK, из которых **нужно установить только три**:

| Компонент | Назначение |
|---|---|
| *vpn-guardian_*.ipk* | Управляющий сервис, DNS policy, TPROXY, watchdog и веб-панель |
| *v2raya_*.ipk* | Совместимая v2rayA 2.5.8 и её core |
| *dnsmasq-full_*.openwrt.ipk* | DNS/DHCP для обычного OpenWrt |
| *dnsmasq-full_*.glinet.ipk* | DNS/DHCP для GL.iNet с сохранённой маркировкой DNS (SO_MARK) и фирменной конфигурацией init |

**Не устанавливайте одновременно оба варианта dnsmasq-full.** Внутри обоих один и тот же пакет *dnsmasq-full* версии 2.90-r5.1. Отдельно приложены SHA-256, сведения об исходном коммите/SDK и исходные архивы dnsmasq 2.90 и v2rayA 2.5.8.

| Архитектура IPK | Целевой OpenWrt SDK |
|---|---|
| *aarch64_cortex-a53* | *mediatek/filogic* |
| *arm_cortex-a7_neon-vfpv4* | *ipq40xx/generic* |
| *x86_64* | *x86/64* |

Это не гарантия работы на каждом роутере с совпадающей архитектурой: дополнительно должны совпадать ABI библиотек, доступность зависимостей и ядро/модули из feeds прошивки. Прошивки с *apk* и MIPS не поддерживаются.

## Установка

Сначала сохраните файл */etc/config/dhcp* и подключитесь по SSH к **IP роутера**, а не через доменное имя или VPN, который будет обновляться. Замена системного DNS/DHCP может временно прерывать разрешение имён.

~~~sh
cp /etc/config/dhcp /root/dhcp.before-vpn-guardian
opkg update
~~~

Скачайте и скопируйте в */tmp* **три IPK одной архитектуры из этого релиза**. На обычном OpenWrt:

~~~sh
opkg install /tmp/dnsmasq-full_*.openwrt.ipk /tmp/v2raya_*.ipk /tmp/vpn-guardian_*.ipk
vpn-guardian init
~~~

На GL.iNet с фирменной конфигурацией dnsmasq:

~~~sh
opkg install /tmp/dnsmasq-full_*.glinet.ipk /tmp/v2raya_*.ipk /tmp/vpn-guardian_*.ipk
vpn-guardian init
~~~

Если установлен обычный *dnsmasq*, а *opkg* сообщает конфликт с *dnsmasq-full*, сохраните конфигурацию и удалите старый пакет *opkg remove dnsmasq*, затем повторите установку. Не игнорируйте несовместимые зависимости. Подробности: [инструкция по установке](https://github.com/Yakwilik/openwrt-vpn-guardian/blob/v0.1.0-rc.3/docs/installation.md).

## Изменения и проверки

- Native dnsmasq разрешает обычные и локальные домены независимо от Guardian; в DNS-прокси попадают только домены VPN-политики.
- Сохраняется выбранный клиентом IP при прозрачной маршрутизации.
- Регулярные выражения Xray/Geosite компилируются в селекторы dnsmasq, обновляются атомарно и подтверждаются через UBus; при ошибках защищённые правила не превращаются в прямые DNS-запросы.
- Сохранены режим VPN-only, прямой трафик и DNS bootstrap. GL.iNet-вариант включает совместимый init и маркировку исходящих DNS-сокетов.
- Пакетный CI проверяет все три архитектуры, оба варианта dnsmasq, содержимое IPK, контрольные суммы и исходные архивы.

На **GL-MT6000** проверены режимы DNS, прямой доступ к Supabase через обычный DNS и WebSocket (3/3 heartbeat), локальные домены и работоспособность VPN. На других моделях **чистая установка в физическом окружении пока не проверена**, поэтому релиз остаётся предварительным (*RC*).

## Отличие от технического тега rc.2

Тег rc.2 не был опубликован как бинарный Release: проверка SDK выявила, что старый сценарий брал неподходящий dnsmasq из базового feed. В rc.3 активный рецепт выбирается однозначно, а собранные IPK проверяются по версии, ELF-архитектуре и нужным функциям.
