# Установка и диагностика

## Совместимость

Пакеты собираются для OpenWrt 24.10 с менеджером пакетов opkg. Используйте feeds от установленной прошивки: из них устанавливаются Xray, nftables, iproute2, CA-сертификаты, geodata и модуль TPROXY.

| Архитектура пакета | SDK target | Платформа |
|---|---|---|
| aarch64_cortex-a53 | mediatek/filogic | ARM64 |
| arm_cortex-a7_neon-vfpv4 | ipq40xx/generic | ARMv7 |
| x86_64 | x86/64 | x86-64 |

Архитектуры, которые принимает роутер:

~~~sh
opkg print-architecture
~~~

Выберите пакеты с соответствующей архитектурой в конце имени файла. Пакеты IPK не предназначены для прошивок с apk; MIPS пока не поддерживается.

## Комплект пакетов

В [Releases](https://github.com/Yakwilik/openwrt-vpn-guardian/releases), в разделе **Assets**, доступны Guardian и совместимая v2rayA 2.5.8 с её собственным core. Рядом опубликованы контрольные суммы, сведения о сборке и исходники v2rayA. Обычный пакет v2rayA из feed OpenWrt 24.10 имеет старый формат базы и не подходит.

Скачайте два файла *.ipk* одной архитектуры из одного релиза, скопируйте их в */tmp* на роутере и установите:

~~~sh
opkg update
opkg install /tmp/v2raya_*.ipk /tmp/vpn-guardian_*.ipk
vpn-guardian init
~~~

Установка пакета сама по себе не включает перехват LAN. Настройка и активация выполняются командой *init* из интерактивной SSH-сессии с правами root. Отдельная установка Go, сборка бинарника и копирование init-скриптов на роутер не требуются.

## Что делает мастер

Мастер проверяет версии и запуск зависимостей, доступ к nftables, policy routing, UCI, ubus, сетевым устройствам, сертификатам и geodata. Затем определяет LAN/WAN, предлагает выбрать разрешённые протоколы и запрашивает подписки. Уже существующие правила маршрутизации сохраняются.

Для новой v2rayA мастер запросит аккаунт. Пароль вводится без отображения и не сохраняется в manifests Guardian. Подписки передаются в v2rayA и не раскрываются в read-only API. v2rayA переводится в backend-only mode с SOCKS на loopback; её собственный transparent proxy остаётся выключенным.

До включения Guardian проверяются оба manifests, конфигурации Xray, синтаксис nftables, доступ к базе и API v2rayA, наличие разрешённых нод и соединение через выбранную ноду. Если активация не проходит, применяется rollback. Установочный сценарий не снимает существующую VPN-only interception при ошибках проверки.

После успешной активации сервисы включаются для автозапуска. DNS-запросы LAN-клиентов на TCP/UDP 53 перенаправляются в отдельный Guardian DNS proxy. Локальные OpenWrt/DHCP-имена всегда разрешаются через dnsmasq. Для внешних запросов в веб-панели доступны режимы system, custom и xray; по умолчанию используется custom с числовыми resolver-ами через VPN только для доменов из VPN routing rules. Отдельный переключатель позволяет применять Custom/Xray ко всему внешнему DNS. DNS самого роутера остаётся на системном/WAN пути и не создаёт bootstrap-зависимость от VPN. Веб-панель работает на LAN-адресе роутера, порт 20175. Nginx не требуется. Если он уже установлен и интеграция доступна, можно использовать HTTP-адрес *vpn.home.arpa*; основной адрес панели мастер показывает независимо от nginx.

## Если проверка не проходит

Исправьте причину из сообщения и повторите *vpn-guardian init*. Мастер не запускает бесконечные попытки настройки в фоне. Если отсутствует только один из двух существующих manifests, восстановите его из резервной копии: потерянные правила не заменяются стандартными.

Проверка готовой конфигурации без изменений:

~~~sh
vpn-guardian bootstrap --dry-run
~~~

Состояние и встроенная проверка работающего стека:

~~~sh
vpn-guardian status
vpn-guardian selftest
~~~

Для автоматизации можно использовать *vpn-guardian bootstrap --non-interactive*. Команда проверяет сохранённые настройки и зависимости, но не читает stdin. При недостающих данных она завершается с ошибкой; завершите настройку через интерактивный *init*.

## Обновление

Установите новый комплект IPK и выполните *vpn-guardian bootstrap* из SSH. Обновление пакетов сохраняет manifests и включённую interception; bootstrap проверяет конфигурацию и применяет новый runtime. Для изменения списка разрешённых протоколов используйте *vpn-guardian init*.

## Сборка для разработки

На компьютере с Go 1.23 или новее:

~~~sh
go test ./...
go vet ./...
go test -race ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o dist/vpn-guardian-linux-arm64 ./cmd/vpn-guardian
~~~

Для воспроизводимой пакетной сборки используются официальный OpenWrt SDK, закреплённые ревизии feeds и точный commit проекта. Рецепты находятся в *package/*, сборочный скрипт — в [scripts/package-openwrt.sh](../scripts/package-openwrt.sh).
