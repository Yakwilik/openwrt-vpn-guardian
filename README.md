# OpenWrt VPN Guardian

Выборочный VPN для OpenWrt: нужные домены и IP идут через VPN, остальной трафик — напрямую. Guardian следит за соединением, переключает недоступные ноды и показывает состояние в веб-панели.

## Установка

Для **OpenWrt 24.10 с opkg**. Доступны сборки для ARM64, ARMv7 и x86-64; [точные архитектуры и требования](docs/installation.md).

1. Откройте [Releases](https://github.com/Yakwilik/openwrt-vpn-guardian/releases) и выберите сборки для архитектуры вашего OpenWrt 24.10 с *opkg*.
2. Скачайте **три IPK** одной архитектуры: *vpn-guardian*, *v2raya* и один *dnsmasq-full* — вариант *.openwrt.ipk* для стандартного OpenWrt либо *.glinet.ipk* для совместимой прошивки GL.iNet.
3. Скопируйте файлы в */tmp* и подключитесь по SSH к IP-адресу роутера. Для стандартного OpenWrt выполните:

~~~sh
opkg update
opkg install /tmp/dnsmasq-full_*.openwrt.ipk /tmp/v2raya_*.ipk /tmp/vpn-guardian_*.ipk
vpn-guardian init
~~~

На GL.iNet с фирменным dnsmasq вместо *.openwrt.ipk* используйте *.glinet.ipk*. **Не устанавливайте оба варианта dnsmasq-full.** Замена dnsmasq может кратковременно прервать DNS/DHCP, поэтому проводите её через локальный SSH по IP; при конфликте со штатным *dnsmasq* см. [инструкцию по замене](docs/installation.md).


Зависимости устанавливаются вместе с пакетами. Мастер настройки проверит их доступность, определит сеть и запросит:

- ссылки на подписки;
- разрешённые протоколы для отбора нод;
- логин и пароль v2rayA, если аккаунт ещё не создан.

При первой установке маршрутизация включится только после проверки конфигурации и VPN-соединения. В конце мастер покажет адрес веб-панели. Повторный *vpn-guardian init* позволяет изменить настройки отбора.

## После установки

Состояние, ноды и подписки доступны в веб-панели. По умолчанию включён **VPN-only**: при отказе VPN backend трафик выбранных сервисов блокируется, обычный direct-трафик продолжает работать.

DNS LAN-клиентов принимает штатный dnsmasq: локальные зоны, DHCP-имена и локальные отрицательные ответы не зависят от Guardian. Обычные внешние домены dnsmasq разрешает через свои системные/WAN upstream-ы; только выбранные VPN-домены передаются в Guardian на loopback. Остановка Guardian не останавливает обычный DNS; в админке доступны System, Custom, Xray и переключатель «только проксируемые домены». Custom/Xray учитывают политику: VPN-only блокирует защищённый DNS при отказе VPN, Fail-open сначала разрешает DNS fallback, а watchdog при подтверждённом отказе переводит весь proxy-класс в deterministic direct; Direct сразу использует системный DNS. Bootstrap роутера работает независимо от Guardian и туннеля, через исходные системные resolver-ы и текущий WAN DNS. Management/WAN-сеть не использует GL-MT как DNS: локальные записи на отдельном upstream-роутере хранятся на нём самом.

Домены и IP для VPN задаются в */etc/vpn-guardian/routing.json*. После изменения:

~~~sh
vpn-guardian validate
vpn-guardian apply
~~~
