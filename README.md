# OpenWrt VPN Guardian

Выборочный VPN для OpenWrt: нужные домены и IP идут через VPN, остальной трафик — напрямую. Guardian следит за соединением, переключает недоступные ноды и показывает состояние в веб-панели.

## Установка

Для **OpenWrt 24.10 с opkg**. Доступны сборки для ARM64, ARMv7 и x86-64; [точные архитектуры и требования](docs/installation.md).

1. Откройте [Releases](https://github.com/Yakwilik/openwrt-vpn-guardian/releases) и выберите сборки для архитектуры вашего OpenWrt 24.10 с *opkg*.
2. Скачайте **три IPK** одной архитектуры: *vpn-guardian*, *v2raya* и один *dnsmasq-full* — вариант *.openwrt.ipk* для стандартного OpenWrt либо *.glinet.ipk* для совместимой прошивки GL.iNet.
3. Скопируйте файлы в */tmp* и подключитесь по SSH к IP-адресу роутера. Для стандартного OpenWrt выполните:

~~~sh
opkg update
opkg install /tmp/dnsmasq-full_*.openwrt.ipk /tmp/v2raya_*.ipk /tmp/vpn-guardian_*.ipk
vpn-guardian init
~~~

На GL.iNet с фирменным dnsmasq вместо *.openwrt.ipk* используйте *.glinet.ipk*. **Не устанавливайте оба варианта dnsmasq-full.** Замена dnsmasq может кратковременно прервать DNS/DHCP, поэтому проводите её через локальный SSH по IP; при конфликте со штатным *dnsmasq* см. [инструкцию по замене](docs/installation.md).


Зависимости устанавливаются вместе с пакетами. Мастер настройки проверит их доступность, определит сеть и запросит:

- ссылки на подписки;
- разрешённые протоколы для отбора нод;
- логин и пароль v2rayA, если аккаунт ещё не создан.

При первой установке маршрутизация включится только после проверки конфигурации и VPN-соединения. В конце мастер покажет адрес веб-панели. Повторный *vpn-guardian init* позволяет изменить настройки отбора.

## После установки

Состояние, ноды и подписки доступны в веб-панели. По умолчанию включён **VPN-only**: при отказе VPN backend трафик выбранных сервисов блокируется, обычный direct-трафик продолжает работать.

DNS LAN-клиентов принимает штатный dnsmasq: локальные зоны, DHCP-имена и локальные отрицательные ответы не зависят от Guardian. Обычные внешние домены dnsmasq разрешает через свои системные/WAN upstream-ы; только выбранные VPN-домены передаются в Guardian на loopback. Остановка Guardian не останавливает обычный DNS; в админке доступны System, Custom, Xray и переключатель «только проксируемые домены». Custom/Xray учитывают политику: VPN-only блокирует защищённый DNS при отказе VPN, Fail-open сначала разрешает DNS fallback, а watchdog при подтверждённом отказе переводит весь proxy-класс в deterministic direct; Direct сразу использует системный DNS. Bootstrap роутера работает независимо от Guardian и туннеля, через исходные системные resolver-ы и текущий WAN DNS. Management/WAN-сеть не использует GL-MT как DNS: локальные записи на отдельном upstream-роутере хранятся на нём самом.

Веб-панель поддерживает именованные группы маршрутов, общие описания, поиск и редактирование. Группы являются только метаданными: их изменение не перезапускает VPN и не влияет на выбор DIRECT/PROXY. Файл *routing.json* хранит их в полях *groups* и *ruleGroups*, сохраняя прежние *proxyDomains*, *proxyIps* и *notes*. Старые файлы без групп поддерживаются без миграции. При сохранении новых правил панель показывает состояние черновика и обновляет его только после подтверждённого ответа API; открытые группы запоминаются браузером.

### Весь трафик через VPN

В админке **Control plane → Режим** содержит единый переключатель **Auto · Direct · Full VPN**. Auto включает выборочные правила и автоматический выбор ноды, Direct — прямой выход, Full VPN — весь поддерживаемый внешний трафик через VPN. При переходе из полного режима прежние правила и DNS-настройки восстанавливаются. Full VPN можно включить и из Direct: панель сначала активирует Auto, затем полный охват; активной показывается только одна кнопка. CLI: <code>vpn-guardian traffic-mode selective</code> и <code>vpn-guardian traffic-mode full-vpn</code>. API: POST */api/control* с действием *traffic_mode* и полем *trafficMode*; требуется существующая авторизация и CSRF-защита.

В *full-vpn* весь внешний IPv4 TCP/UDP от устройств LAN и внешний DNS идут через текущий VPN-backend, независимо от списка доменов и IP. Сбой VPN не разрешает прямой выход. Локальные адреса, DNAT-ответы и служебный трафик самого роутера сохраняют прежнее поведение. Внешний IPv6 и другие протоколы (включая ICMP), которые текущий прозрачный прокси не обслуживает, блокируются от утечки, а не туннелируются. Это полный охват поддерживаемого клиентского трафика, не системный IP-туннель всего роутера. Выбранный режим QUIC продолжает действовать.

Исходные маршруты, группы и DNS-предпочтения не перезаписываются. В полном режиме DNS использует защищённый all-domains runtime; *System* временно заменяется *Custom* в runtime, без изменения сохранённой конфигурации. Возврат в *selective* восстанавливает выборочную обработку DNS. Режим сохраняется после перезагрузки; он виден как *trafficMode* в control API и *traffic_mode* в статусе. При переключении перезапускается только *vpn-front*, поэтому существующие клиентские соединения могут кратко прерваться. Перед операцией создаётся резервный архив, кандидаты Xray/nftables проверяются, при ошибке предусмотрен откат. Fail-open в полном режиме недоступен. Нажатие Direct запрашивает подтверждение и сначала отключает полный охват, а затем включает прямой выход.

### Совместимость HTTP/3 и выборочной маршрутизации

При нестабильной работе QUIC можно включить явный возврат к TCP на стороне роутера:

~~~sh
vpn-guardian quic-mode tcp-fallback
~~~

Команда атомарно меняет только таблицу nftables Guardian и поле *front.quicMode* в *stack.json*. Сервисы Xray, DNS и VPN-backend не перезапускаются, доменные правила и выбранная нода сохраняются. Настройка переживает перезагрузку и последующий *apply*.

В режиме *tcp-fallback* внешний UDP/443 от LAN-клиентов не попадает в TPROXY и получает ICMP port-unreachable, а не молча отбрасывается. Это позволяет браузерам, поддерживающим возврат к TCP, использовать HTTP/2 или HTTP/1.1. **Ограничение действует на весь внешний клиентский UDP/443**, включая приложения без TCP fallback; это режим совместимости, а не исправление реализации QUIC. Остальные UDP-порты, локальные адреса, DNAT и исходящий VPN-транспорт самого роутера не меняются. IPv4 и IPv6 охвачены запретом, чтобы IPv6 не обходил режим.

Обратное переключение:

~~~sh
vpn-guardian quic-mode allow
~~~

Отсутствующее поле *front.quicMode* означает прежний режим *allow*. Текущее значение также появляется в *quic_mode* ответа API статуса и в диагностических снимках. Перед изменением сохраняется архив для отката. Наличие успешных HTTP-проверок само по себе не доказывает устранение зависания браузерного интерфейса; для такого вывода нужен повторный клиентский тест.

В админке доступна панель **QUIC / HTTP/3** с переключением *TCP fallback* / *Allow QUIC*. Переключение через POST */api/control* (действие *quic_mode*, поле *quicMode*) использует ту же атомарную операцию и проверку авторизации/CSRF, что CLI. Закрытый для неавторизованных пользователей GET */api/quic* возвращает текущий и фактически применённый режим, количество отклонённых UDP/443-пакетов из nftables и последние диагностические события QUIC/HTTP/3 из постоянного журнала. Счётчик отказов — **не число ошибок**, он обнуляется при переустановке правил. Ошибки самого браузера на роутер автоматически не попадают.

### Постоянная диагностика

Служба *vpn-guardian-diagnostics* запускается при старте роутера, не управляет VPN-нодами и не меняет маршрутизацию. Она сохраняет журнал системных ошибок и событий Guardian, изменения состояния процессов, DNS/VPN и результаты контрольных HTTPS-запросов **на постоянный раздел OpenWrt**, а не в очищаемый после перезагрузки */tmp*:

- */etc/vpn-guardian/diagnostics/events.log* — ошибки Xray, DNS, v2rayA, watchdog, procd, переключения нод, перезапуски PID и изменения статуса.
- */etc/vpn-guardian/diagnostics/health.jsonl* — снимки состояния Guardian, процессов, доступной памяти и conntrack с ISO-временем (не реже одного раза в минуту, при изменениях — сразу).
- */etc/vpn-guardian/diagnostics/probes.jsonl* — раз в две минуты контрольные GET-запросы: Yandex через DIRECT, YouTube/ChatGPT/Notebook через SOCKS Guardian. Сохраняются только HTTP-коды, задержки и сетевые ошибки, но не содержимое страниц, токены или cookies.

Каждый поток ограничен **2 МиБ + 3 ротации**, всего не более ~24 МиБ. Права на каталог 0700, файлы 0600; журналы не включаются в архив конфигураций Guardian и сохраняются после обычной перезагрузки. При вызове *vpn-guardian cleanup* исторические журналы сохраняются для расследования и могут быть удалены вручную.

Для быстрой проверки: <code>vpn-guardian diagnostics -mode once</code>. Для просмотра: <code>tail -n 100 /etc/vpn-guardian/diagnostics/events.log</code>. Исторические части *.1*, *.2* и *.3* содержат предыдущие записи. Для проверки службы: <code>/etc/init.d/vpn-guardian-diagnostics status</code>. Снимки отражают состояние самого роутера; они не доказывают отсутствие ошибок JavaScript или зависаний браузера на клиентском устройстве.

Домены и IP для VPN задаются в */etc/vpn-guardian/routing.json*. После изменения:

~~~sh
vpn-guardian validate
vpn-guardian apply
~~~
